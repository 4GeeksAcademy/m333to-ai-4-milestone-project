# Major Implementation Learning Rule

## Rule

After every major implementation, create a lesson-style Markdown file in the root-level `masterLearnings/` directory.

## Scope

**Always active** for every major implementation that changes the project structure, architecture, user-facing behavior, backend behavior, agent capability, workflow, or development process.

## Required lesson content

Each lesson must explain:

1. **Reason:** Why the implementation was needed and what problem it addresses.
2. **Implementation:** What was changed, including important files or directories.
3. **Design choices:** Why the chosen approach was preferred over reasonable alternatives.
4. **Learning takeaway:** What the developer can learn from the implementation.
5. **Verification:** How the implementation was tested or verified.
6. **Next steps:** What could be improved or built next.

The lesson should be understandable as a standalone learning resource and should not be limited to a list of changed files.
